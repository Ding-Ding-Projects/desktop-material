⚡ The thirty-second answer 三十秒答案

Neither replaces the other. Choose the operating model. 兩個唔係互相頂替；你係揀運作模式。

Cheap LFS is a Desktop Material feature with guided review, provider-first upload, explicit restore checks, and Release/OCI storage. Git LFS is a standard Git extension with a broad client, host, CLI, locking, and migration ecosystem. Cheap LFS 係 Desktop Material 功能，有審閱介面、provider-first 上傳、明確還原檢查同 Release／OCI 儲存。Git LFS 係標準 Git extension，client、host、CLI、locking 同 migration 生態更闊。

🚀 The exact publication handoff 精確發佈交棒

Cheap LFS pins first. Then ordinary Git publishes the pointer. Cheap LFS 先 pin；之後普通 Git 發佈 pointer。

This sequence matters. Running git push on a raw unpinned file does not magically turn it into Cheap LFS. The app must finish the provider transaction and create the pointer commit first. 次序好重要。對住未 pin raw file 跑 git push 唔會魔法變 Cheap LFS；app 要先完成 provider transaction 同建立 pointer commit。

  1. 01 🧭

    Preflight the real push remote Preflight 真正 push remote

    Resolve the canonical GitHub repository, authenticated account, local branch, push URL, and expected remote state before provider upload or remote mutation. Provider upload 或 remote mutation 前，先解出 canonical GitHub repo、登入 account、本機 branch、push URL 同預期 remote state。

  2. 02 ⚓

    Anchor a first Release branch 第一次 Release branch 先落錨

    Only when Release storage needs its first remote branch, the app may create and prove a create-only anchor. An OCI route needs no Release anchor. 只係 Release storage 第一次需要 remote branch 時，app 先可能建立同證明 create-only anchor。OCI 路線唔使 Release anchor。

  3. 03 ☁️

    Upload, reread, and verify bytes 上傳、重讀、驗證 bytes

    The stream must consume the reviewed source exactly. The returned asset state, identity, and size are checked; any provider digest is checked when present; then the source is revalidated. Stream 要精確食晒已審 source；再驗 returned asset state、identity、size，有 provider digest 就一併驗，最後 revalidate source。

  4. 04 🧾

    Review and commit the pointer 審閱再 commit pointer

    Only verified provider facts become a pointer. Review the staged change and commit it through Desktop Material. 只有已驗 provider fact 先變 pointer；喺 Desktop Material 審 staged change 再 commit。

  5. 05 🚀

    Run ordinary git push 跑普通 git push

    The later push carries the Git commit containing the Cheap LFS pointer. It does not duplicate the provider upload. 之後 push 帶住含 Cheap LFS pointer 嘅 Git commit；唔會重複 provider upload。

  6. 06 ✅

    Prove the remote tip and restore 證明 remote tip 同還原

    Fetch, prove that local HEAD equals its upstream, then exercise a fresh restore instead of declaring victory because the terminal looked cheerful. Fetch 後證明本機 HEAD 等於 upstream，再做 fresh restore；唔好見 terminal 笑騎騎就當畢業。

🧭 Cheap LFS

Inspect, publish, and prove 檢查、發佈、證明 

git remote get-url --push origin
git show HEAD:path/to/large-file.bin
git push
git fetch origin
git rev-parse HEAD
git rev-parse '@{upstream}'

The last two SHAs must match. git show reads the committed pointer even when Desktop Material has materialized raw working bytes over it. 最後兩個 SHA 必須一樣。即使 Desktop Material 已將 raw working bytes 還原覆住 pointer，git show 仍讀到已 commit pointer。

🌍 Git LFS

Track, commit, and push Track、commit、push 

git lfs install
git lfs track "*.psd"
git add .gitattributes artwork.psd
git commit -m "Track artwork with Git LFS"
git push

The clean filter records the pointer. The installed pre-push hook uploads missing objects before Git finishes the ref update. Clean filter 記錄 pointer；已安裝 pre-push hook 喺 Git 完成 ref update 前上傳 missing object。

⚠️

Do not add restored raw bytes 唔好 add 還原後 raw bytes

CLI git status may show the intentionally materialized file as modified. Do not git add it over the committed pointer. CLI git status 可能將刻意 materialize 嘅檔案顯示 modified；唔好 git add 佢覆蓋已 commit pointer。

🪝

Manual upstream publication is not the app anchor 手動 upstream 發佈唔等於 app anchor 

git push --set-upstream origin HEAD

That is an ordinary branch publication: it may update an existing fast-forwardable branch and it runs normal hooks. It is not equivalent to Desktop Material’s create-only, hook-skipping Release anchor. 呢個係普通 branch publication：可更新既有 fast-forwardable branch，亦會跑正常 hook。佢唔等同 Desktop Material create-only、skip hook 嘅 Release anchor。

🛤️ The machinery under the pointer pointer 底下部機器

Provider-first versus hook-driven. Provider-first 對 hook-driven。

🧭 Cheap LFS

  1. Review.審閱。 The app checks the tracked path, source identity, size, provider, remote, and branch context.app 檢查 tracked path、source 身份、大小、provider、remote 同 branch context。
  2. Anchor when required.需要先落錨。 A first Release-backed publication may create and prove a branch anchor before heavy bytes move.第一次 Release-backed 發佈可能要先建立同證明 branch anchor。
  3. Upload and verify.上傳再驗。 Provider objects are checked before the source is replaced by a pointer.provider object 驗明正身，先用 pointer 換走 source。
  4. Commit and push.commit 再 push。 The pointer enters Git, then an ordinary push publishes that pointer commit.pointer 入 Git，之後普通 push 發佈 pointer commit。
⚠️

After Desktop Material restores raw bytes over a committed pointer, CLI Git may show the file as modified. Inspect the committed pointer with git show HEAD:path/to/file; do not accidentally add the materialized payload.Desktop Material 將真 bytes 還原覆住已 commit pointer 後，CLI Git 可能顯示 modified。用 git show HEAD:path/to/file 睇已 commit pointer；唔好手快 add 咗真 payload。

🌍 Git LFS

  1. Track.追蹤。 git lfs track writes filter attributes; the attributes must be committed.git lfs track 寫 filter attributes；attributes 要 commit。
  2. Clean.轉 pointer。 The clean filter writes a standard LFS pointer to Git and keeps content in the local LFS object store.clean filter 將標準 LFS pointer 寫入 Git，content 留喺本機 LFS object store。
  3. Commit.Commit。 Git records the pointer and the .gitattributes policy.Git 記錄 pointer 同 .gitattributes policy。
  4. Push.Push。 The pre-push hook sends missing objects through the LFS batch/transfer protocol before Git completes the ref update.pre-push hook 先經 LFS batch／transfer protocol 送 missing object，再畀 Git 完成 ref update。
🪝

A missing or bypassed pre-push hook can leave a pushed pointer whose object is unavailable. git lfs push --all and host diagnostics are the recovery toolbox—not a Release asset handoff.漏咗或者避過 pre-push hook，可以 push 咗 pointer 但 object 唔到位。救援工具係 git lfs push --all 同 host 診斷，唔係 Release asset 交接。

🚧

The pointers are not interchangeable. 兩款 pointer 唔可以互換。

Git LFS clients do not understand a desktop-material/cheap-lfs/v1 pointer, and Desktop Material does not claim its provider pointer is a Git LFS v1 object. Migration means materialize, choose the destination model, and repin/retrack deliberately. Git LFS client 唔識 desktop-material/cheap-lfs/v1 pointer；Desktop Material 亦冇扮佢係 Git LFS v1 object。搬遷要先 materialize，再揀目的模型，刻意 repin／retrack。
